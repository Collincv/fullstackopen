** Asynchronous callbacks from 2.C
- helps with problems associated with blocking which is inherint due to JS single threaded nature
- an example of blocking is when a part of the program takes a long time to run, everything else on the web page is frozen.  cant do anything else until it finishes running.  the commands, clicks etc are still read, but they wont execute until it finishes its current thing
- Asynchronous handles this by below , through concurrency and the event loop. works bc runtime can only do one thing at a time, but the browser has access to other things outside of the runtime.  concurrency kicks in on other pieces of the browser:
  [[file:./images/20260111_173800.png]]
- event loop looks at the stack and looks at the tasks (callback queue).  Ifi the stack is empy, it takes the first thing of the queue, and pushes it onto the stack
- set timeout 0
- settimeout is not a guaranteed time to execution.  It is a minimum time to execution
- callbacks - a function that another function calls, or an asynchronous callback
- synchronous vs asynchronous - no set timeout vs set timeout:
  [[file:./images/20260111_175526.png]]
[[file:./images/20260111_175701.png]]
- browser would like to repaint the screen as fast as its frame rate. constrained by what is going on in js.  cant render if there is code in the stack .  Render is like its own callback queue.  But it is given a higher priority than callbacks.  every 16 milliseconds, it queues a render, and whats for the stack to clear before it can do a render.
- while its blocked with things on the stack, cant change things on the screen.  cant click things and see a response:
  [[file:./images/20260111_180449.png]]
- render given a chance between each element, bc queued up asynchronously and has higher priority than the callback queue.  so it can squeeze itself in:
  [[file:./images/20260111_180609.png]]
